# 监控页压测抽屉

## 目的

监控页头部原本同时展示压测 prompt、并发数量和启动按钮，导致刷新控制与压测参数混在一起。现在通过右侧抽屉将这些参数收敛到独立面板中，页面头部只保留一个「压测设置」入口。

## 组件结构

- `components/ui/drawer.tsx`：通用右侧抽屉，负责遮罩、Esc 关闭、滚动锁定和过渡展示。
- `components/monitor/load-test-drawer.tsx`：压测业务面板，包含 prompt、并发数、启动操作、进度、错误和结果摘要。
- `components/monitor/stat-card.tsx`：监控页和压测抽屉共用的指标卡片。
- `lib/monitor/formatters.ts`：统一格式化内存、耗时、数字和时间。

## 交互约定

- 点击页面头部的「压测设置」打开抽屉；抽屉关闭后已输入的参数会保留。
- 「开始压测」在抽屉内提交，请求仍走 `/api/load-test`，并通过轮询任务状态更新进度。
- 压测运行中，页面头部入口显示「压测中 已完成/总数」，参数输入会被禁用。
- 结果摘要直接展示在抽屉内，避免监控页主内容被一次性压测数据打断。
- 结果包含完整的核心指标和压测期间出现过的进程明细，抽屉内容可滚动查看。
- 压测 prompt 区域提供「如何触发多 Agent」说明；模型支持多 Agent 时，明确要求创建、等待并关闭子 Agent 更容易触发内置协作工具。

## 维护说明

如果新增压测参数，优先扩展 `LoadTestDrawer` 内的表单和提交 payload，同时保持参数校验文案与 `maxLoadTestConcurrency` 一致。不要把新参数重新放回监控页头部。

## Codex stdio 自定义工具调用

压测抽屉提供「Codex stdio 自定义工具调用」复选框，默认开启。开启时 `/api/load-test` 会在每个请求中注册 `project_tools` stdio MCP server；关闭时请求不再注入该配置。可用工具是 `get_project_info` 和 `read_project_file`，prompt 中显式写出“请调用 xx 工具”最容易被模型触发。

## 多 Agent 触发

`streamCodexReply` 已在 Codex 配置中启用 `agents.enabled = true`，并注册 `game_designer` 和 `game_developer` 角色。实际是否出现 `spawn_agent` 调用仍取决于模型能力。压测时可以使用类似 prompt：「请创建 1 个 game_designer 子 agent 设计一个浏览器小游戏玩法；等待它完成后，用一句话汇总最终玩法和操作方式。」
